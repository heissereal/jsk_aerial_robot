# C/D連続移動：圧力遅れを含む予測制御

この文書は旧反復探索方式の設計記録です。2026年9月30日の単発試験方式への
変更後、下記の反復探索・候補MPCはアクチュエータ指令に使用しません。
現在の動作・設定・診断は [単発試験と連続牽引](hybrid_single_pass.md) を参照してください。

## 今回の実装範囲

`inchworm_action_c:=true` で使用する、Action C唯一の実行経路です。
外側の条件探索だけでなく、動作中に左右別の推力・圧力・加圧切替時刻を
再計画する内側の制御を実装しています。ただし、現在のMuJoCo比較版では
力成分の配分を駆動中に保持しており、配分移行時間の最適化は未成立です。
**停止・再把持後にも残る安定した前進は、まだ物理検証を通過していません。**
旧Cのパルス処理・最適化・減少専用の残留推力処理は削除しました。
旧版はコミット `0a2db4956` に保存されています。
Action A/B/D、rocking、共通の姿勢復帰、MotorInfo、ファームウェアは維持します。
起動だけでは移動しません。新しい制御の前進性能は実機では未検証です。

```text
再把持後の状態 + 過去の実試行
          ↓
外側：底面圧 Pbottom と水平割合の始点 m_min を選ぶ
          ↓（移動中は必要に応じ底面を低速調整）
内側：圧力遅れ・実測角/角速度・幾何モデルで候補を予測
      左右の伸展時推力、屈曲時推力、屈曲圧、加圧開始時刻
          ↓ 最初の短い区間だけ適用、次回は実測から再計画
実測角による鉛直力制限・左右差/rollの抑制 → 圧力/推力出力
          ↓
目標付近で減速・再把持・底面0指令 → 安定平均x変位と総時間を評価
```

### 外側：2変数は動作全体の自由度ではない

- `Pbottom`: 0–30 kPa。初期値から始め、必要に応じ移動中も低速で変更。
  姿勢復帰・開始位置評価・終了位置評価時は0指令へ。
- `m_min`: 0–1。予測する前進・上向き力について
  `m = max(Fx,0) / (max(Fx,0) + max(Fup,0) + ε)` と定義。
  力の成分の比であり、アーム角そのものでも移動量の割合でもありません。
- 現在のMuJoCo比較版では、駆動中は選んだ `m_min` の力成分配分を保持します。
  以前の時刻だけによる `m_min → 1` は、推力が立ち上がる前に水平側へ戻り、
  配分を変えても荷重軽減がほぼ変わらない問題がありました。
  再把持時に加圧し、支持を受け渡します。この比較版で `duration` は旧診断値として
  残っていますが、実際の駆動時間・力配分移行時間を最適化できているとは扱いません。
  `m_min=1` は最初から水平牽引を目指す連続滑り探索です。
  実際に鉛直力が厳密に0になることは保証しません。
  小さくすると駆動中の上向き成分を増やす方向で予測候補を評価します。
- 再把持後の前後平均角/左右差、Spinal roll/pitch、前後実測圧力を
  接触状態の比較に使います。摩擦係数や接触面積を直接同定する実装ではありません。
- 近い状態の結果を比較する粗いオンライン試行選択です。GP/ベイズ最適化やSACではありません。
  再把持後も前進が残れば、その条件を継続して目標へ進みます。
  残る前進が2 mm未満（小さい残目標では目標の半分未満）なら、同じmを再試行し続けません。
  既知の有効な低消費条件があれば戻し、なければmを1→0.75→0.5→0.25→0と粗く変更。
  配分比較中は直前の底面指令を固定します。一巡しても進まなければ底面を5 kPa変更し、
  再び滑り側から試します。姿勢・角度・推力の安全上限は全候補に適用します。
  最大64試行をプロセス内に保持し、方向反転時はリセットします。
  再起動をまたぐ保存・再利用はありません。
- 移動中はまず推力を探索。上限到達または実出力が制約で抑えられた状態で
  平均速度未達が2秒続き、rollが8度以内・角速度が0.1 rad/s未満なら、
  底面目標を5 kPa増やす方向へ **1 kPa/s** で変更します。
  その間は推力探索目標を保持（角度・姿勢FBによる減速は有効）。
  圧力追従後に再開し、追従しなくても8秒で探索目標の保持を解除します。
  速度が出たら底面を保持。予測不成立だけを理由に底面を増やしません。
  これは実測速度に基づく段階的な補助探索で、底面による改善を保証する
  ベイズ最適化ではありません。動作中に底面を変更した区間は、単一の固定底面
  条件の試行として外側のbestへ記録しません。設定を継続して利用することと、
  条件の優劣を学習済みと認定することを分離しています。

評価は、開始・終了の安定した平均x位置の差に対する累積推力使用を中心にします。
推力二乗積分はエネルギーの代理指標で、電力計によるJ単位の消費ではありません。
時間で割って平均化せず、待機して消費コストを薄める抜け道を防ぎます。
両端は底面0 kPa指令、実測±5 kPa以内、再把持圧に到達、推力ほぼ0で測定します。
連続0.8秒の時間加重平均を使用し、4分割した小窓の平均位置の幅2 mm以下・
窓内速度2 mm/s以下、底面圧の小窓平均の幅1 kPa以下・変化速度1 kPa/s以下、
roll角速度0.1 rad/s未満が必要です。静止中のmocapノイズだけで待機し続けないよう、
生データの最大値−最小値では判定しません。ただし最新値が全窓平均から
許容幅の2倍を超えて離れた場合は、急変としてその窓を採用しません。
古い値・同一stampの重複・0.25秒超の欠落は有効な窓として扱いません。
安定した両端が取れない試行は瞬間値で代用せず、外側学習から除外します。
実測圧が低くても、底面が完全に潰れたことや同一接触状態を保証するものではありません。
準備・待機・姿勢復帰も時間に含め、推力二乗積分・復帰時間・目標未達を減点します。
動作中の最大変位を報酬にはしません。未完了動作には正の前進報酬を付けません。
予測不成立後も安全に減速・再把持を完了した場合は、その時点の正味変位を評価します。
探索中の前進も同じ絶対mocap目標に加算されます。残り1 mm以下で減速・再把持し、
終了側の安定平均でも到達していれば終了、戻った場合は残り距離を自動で続けます。
復帰が挟まって安定した終了窓がない場合は、成功試行として記録しません。
手動介入の完全な識別はできません。

現在の評価式（秒・N、前進量はmm）：

```text
effort = integral(sum(T_i^2) dt)  # 姿勢復帰も含む推力使用の代理量
cost_per_mm = (effort + 0.01 * total_seconds + 0.1 * recovery_seconds) / retained_mm
J = 1 / (1 + cost_per_mm)
```

この正の評価は安全に再把持し、十分な前進が残った試行だけに与えます。
それ以外は負の評価とし、未達・後退・消費・時間・安全停止を減点します。
出力ゼロで動かない条件は有効な前進条件より上位になりません。
大域的な最小エネルギー解を保証するものではなく、少ない実試行で使える条件を選びます。

無効な通電の継続を防ぐため、駆動窓で6秒以上、推力二乗積分24 N²s以上を使い、
mocapの平均位置が2 mmも進まなければ減速・再把持して次条件を選びます。
前進している窓は更新して継続するため、単なる6秒の停止タイマーではありません。
この暫定予算は電気エネルギー上限ではなく、実機での性能は未保証です。
配分切り替えは再把持後に行い、接触中の圧力波形を無条件に切り替えません。

### 内側：圧力応答を予測して先に指令する

0.1秒ごとに2秒先を0.05秒刻みで予測します。探索対象は左右各々の
伸展側推力・屈曲側推力・屈曲圧・圧力切替時刻です。旧来の `duration`
候補は残っていますが、現在は力配分を変更しないため、有効な移行時間探索とは扱いません。
毎回の予測末尾で推力を0にする条件や、3秒経過による再把持はありません。
目標到達の確認・予測不成立・実測保護・総時間制限が停止を管理します。
有限候補の座標探索なので、連続最適解や大域最適性は保証しません。

- 加圧/排気速度とむだ時間を、実際の圧力目標・圧力応答から更新。
  移動に失敗しても再加圧中の計測は利用します。
- 同時に加圧する前方2本と底面の負荷を簡略に2分類します。
  後方加圧中の供給競合やポンプの完全なモデルではありません。
- 静的な圧力―推力―角度テーブルの**変化量**を現在角に加え、
  実測角速度と小さな局所補正で将来の屈曲を予測します。
  角加速度の局所補正は `bias * tau * (1-exp(-t/tau))` として角速度へ加えます。
  ノイズを含む補正を `bias*t` で予測末尾まで積み上げることはしません。
  アーム角はロータ直下Neuron基準、0°伸展・正方向屈曲です。
  パルス中はSpinalの回転を除いた相対gyroを積分します。
- 例えば25 kPa到達に約1.2秒かかる応答なら、圧力目標を出した瞬間に
  曲がったことにはせず、その遅れを含めて早めの加圧候補を評価します。
  屈曲側に切り替えた腕を、再計画で伸展側へ戻さないラッチがあります。
- 6.5°のロータ傾斜と実測アーム角から、前進/上向き成分・rollモーメントを推定。
  屈曲中の推力増加も候補に含めます。減少しかできない残留推力ではありません。
- 目標速度未達ならAction Dのように各前方ロータの推力探索目標を増やします。
  既定は1 Nから開始し、実行可能な駆動中の0.5秒窓の平均前進速度が
  5 mm/s未満なら0.5 Nずつ上昇、満たせば維持します。後退も未達に含みます。
  速度自体も直近0.5秒のmocap回帰直線から求め、1サンプル差分は使いません。
  探索目標は候補推力の上限でもあり、初期から6 N候補へ飛びません。
  実際の増加速度は最大1 N/s。これは強制的な最低出力ではありません。左右の角度・roll・
  上向き力制限が優先し、候補不成立時の増強や待機中の積み上げはしません。
  安全な試行間では目標を保持し、方向反転・ノード再起動で初期化します。
  `hybrid_locomotion_search_initial_thrust_n`、`hybrid_locomotion_search_thrust_step_n`、
  `hybrid_locomotion_search_interval_sec`で初期値・刻み・判定時間を設定します。
 失敗試行を理由に探索上限を3 Nへ下げる処理はありません。

### MuJoCo物理検証中の修正（2026-09-30）

まだ再現性のある目標到達を保証しない開発版です。単体テストの合格を前進成功と
扱わないでください。物理結果は `hybrid_mujoco_validation_20260930.md` に記録します。

- Debugビルドでも予測ソースをO2でコンパイルし、圧力・時間候補の評価順を巡回。
  0.8 N / 10 kPaの粗い候補だけでなく、0.1 N / 1 kPa級の小さい候補も予測検査。
  実行時の推力勾配・角度・姿勢保護は残します。
- 前方2基の水平要求の内部上限を12 Nへ整理。**1基の上限は6 Nのまま**です。
- 再把持は後方2本の実測圧24〜28 kPaで前方推力を減らし、底面も順次減圧。
  支持点を仮定した横力の釣合いも予測と実行の双方に含めます。
- 駆動中の到達判定には、接触支点高さとpitch変化による揺動分の余裕を見込みます。
  報酬と最終到達判定は補正した推定位置ではなく、停止後の実測平均xです。
  終端では3秒窓のpitch安定も確認。**pitch姿勢復帰を有効にした変更ではありません。**
- `hybrid_locomotion_sliding_rear_pressure_kpa`（既定0、最大6）を指定すると、
  駆動中の後方目標はこの値×mになります。5 kPaはMuJoCoの比較条件であり、
  実機既定へは反映していません。
- `hybrid_locomotion_retain_grasp_pressure`（既定false）の比較では、再把持後も
  前方2本の大きい方の屈曲圧を双方に保持します。到達成功時だけGRASPにも引き継ぎ、
  手動停止・異常停止・enableの切替では通常の基本圧へ戻します。
- `hybrid_contact_position_main_body_m`はハイブリッド制御専用の支点仮定。
  検証のz=-0.12 mは100 mm円筒の接触位置を参考にした値で、自動同定値ではありません。
  共通姿勢復帰の支点や実機既定のz=-0.07 mは変更していません。
  推力上限自体は常に6 N以下です。姿勢復帰の4 N上限は変更しません。
- 旧 `duration` 候補の範囲は0.5–3秒です。
  `hybrid_locomotion_run_max_sec` は互換性のため名前を残していますが、
  現在はこの旧候補の上限であり、推力を切るタイマーではありません。
- 接触・滑りの正確な変位モデルはないため、内側は力成分と姿勢/角度を評価し、
  **本当に進んだかは外側の実測変位で評価**します。

候補は公称・遅い・速い・左右非対称2通りの5応答で検査し、最悪コストを比較します。
これらは経験的な検証シナリオであり、保証付きロバストMPCではありません。
既定12 msの計算予算を候補間で検査し、評価を完了した最良候補だけを適用します。
OSスケジューリング等を含む厳密なリアルタイム期限は保証しません。

### 制約と所有権

- 前方2本だけを正推力で駆動。後退時は前後ペアを反転。
  後方は移動中減圧、再把持時に基準圧へ戻します。
- アーム圧50 kPa以下、移動推力6 N以下（出力経路の設定が低ければそちらを優先）。
- 底面目標0〜5 kPaでは到達許容を±5 kPaとし、開始・残留rollの整定判定に
  共通適用します。5 kPaを超える目標では従来の圧力許容（既定±2 kPa）です。
- 上向き力は計画時と実測角による出力時の双方で制限。
  既定は6 Nと機体重量の60%の小さい方。人体への接触力制限ではありません。
- 実測角・相対伸展量・左右差・roll/角速度・相対pitch変化・後退量を監視。
  故障・古いセンサ・実測角度等の制限超過は停止し、自動再試行しません。
  現在の圧力・推力を保持する候補も5応答で検査します。それでも全候補が不成立なら
  推力を増やさず減速・再把持し、目標を保持して再探索します。
  したがって、あらゆる接触状態で出力が途切れないことを保証する変更ではありません。
  実測roll超過時の既存の共通姿勢復帰への引き継ぎは維持します。
- 動作中の一時的rollと、静止/圧力整定後の悪化するrollを区別。
  大きなroll/角速度は即時に共通復帰へ渡し、通常の残留roll判定は境界だけ。
  復帰中は新しい移動制御は出力せず、成功後に保存した目標へ自動再開します。
- 旧Cの実行分岐・外側最適化・圧力pull処理は存在しません。
  外側探索を無効にしても内側の予測制御は動作します。
- 総180秒の制限は復帰中にも有効。試行準備60秒、低圧平均の測定を含む再把持20秒の期限もあります。
  既定の最大10試行、最大5回の姿勢復帰も維持します。これらの上限やタイムアウト、
  明示的な停止指令による終了は自動再開しません。正常時は途中の定期的な再把持なしに
  駆動を継続しますが、予測不成立や姿勢復帰を無視するものではありません。

## 起動と確認

まず固定した非人体の試験体・MuJoCoで確認してください。
実機での動作成立や安全性を保証する設定ではありません。
同じロボットに複数のattitude/pressure controllerを立てないでください。

既存のbridge等を起動済みで、attitude/pressure controllerが未起動の場合：

```bash
roslaunch hugmy attitude_pressure_controller.launch \
  inchworm_action_c:=true \
  hybrid_locomotion_outer_enabled:=false \
  hybrid_locomotion_initial_bottom_kpa:=5.0 \
  hybrid_locomotion_initial_m:=1.0
```

移動制御の新旧切替・shadow引数は削除しました。Cを有効にして移動指令を出すと、
新しい予測制御が実際に出力します。外側探索は
`hybrid_locomotion_outer_enabled:=true` で有効になります。
まず外側を固定して内側の圧力・屈曲予測を確認できます。

MuJoCo bringupで一括起動する場合も上記hybrid引数を渡せます：

```bash
roslaunch hugmy bringup.launch \
  simulation:=true real_machine:=false mujoco:=true fixed_arms:=false \
  spawn_human:=true \
  mujoco_initial_arm_pressure:=30 mujoco_initial_bottom_pressure:=0 \
  headless:=false start_attitude_allocator:=true inchworm_action_c:=true \
  hybrid_locomotion_outer_enabled:=false
```

起動だけでは移動しません。従来どおり目標姿勢・enable・inchworm指令を与えます。
`spawn_z`はMuJoCoの初期位置には反映されません。円筒を出す場合は
`simulation/pneumatic/perching_initial_clearance`（円筒上面から本体原点まで、
既定65 mm）を用います。0で旧MJCF位置を使用します。飛行用起動は変更しません。
初期圧引数はシミュレーション専用で、省略時はYAMLの設定を維持します。
加圧済みの把持試験を再現するための引数で、実機を自動加圧する機能ではありません。
移動量はmocapの符号付きxを使用するため、試験体と機体の前後軸を合わせてください。
任意yawに追従して進行軸を再登録する機能は今回追加していません。
launch引数は起動時に読みます。動作中のrosparam変更では切り替わりません。
姿勢復帰専用の `recovery_predictive_shadow` は別機能で、その設定は変更していません。

### ログ

`Hybrid C/D candidate`：選んだ外側条件。
`Hybrid C/D MPC`：実際に再計画した左右推力・圧力・切替・時間と成立判定。
`Hybrid C/D result`：再把持/復帰後の正味変位、総時間、推力使用、評価値。
`Hybrid C/D evaluation`：低底面圧の平均評価が有効か、開始/終了の平均xと終了圧。
停止時は診断配列を出す前に終了するため、最終平均はこのログで確認してください。

`/quadrotor/attitude_pressure_controller/hybrid_locomotion` はFloat32MultiArray：

### cd_5の圧力ピーク・準備待ち対策

ハイブリッド経路にも独立した圧力到達ヒステリシスを適用する。
初回到達は従来の±2 kPa、到達後は±5 kPaを保持範囲とし、
それを超えても偏差8 kPa以内なら0.10秒だけ許容する。
再把持・新しい試行では到達判定をリセットする。位置と底面圧の安定窓、
姿勢条件、センサ鮮度は従来どおりで、圧力到達だけで準備完了にはしない。

実測アーム圧が指令上限+5 kPa（既定45 kPa）を超えた場合、
`pressure_safety_confirm_sec`（既定0.08秒）の確認中は推力・圧力・底面の
駆動指令を保持し、推力探索とモデル観測更新を保留する。
正常圧に戻れば継続、超過が持続すれば把持へ停止する。
60 kPaの生値上限、非有限値、−5 kPa未満、古い圧力情報は即停止。
角度・角速度・姿勢制限は確認猶予中も有効。
再把持中の推力低下など安全側の処理は止めない。
推力上限・基本波形・再把持波形は変更していない。

診断配列の既存0〜52番は維持し、53番に過圧確認中、54番に準備/再把持の
圧力到達ラッチを追加した。以前の汎用角度エラーとは別の圧力停止理由を出す。

```bash
python3 robots/hugmy/test/test_hybrid_pressure.py
python3 robots/hugmy/test/test_hybrid_pressure.py /path/to/walk_inchworm_cd_5_2026-09-30-01-52-43.bag
python3 robots/hugmy/test/smoke_hybrid_locomotion_ros.py --pressure-guards
```

bagリプレイでは40.94秒・62.66秒の単発ピークは停止せず保留後継続。
準備中の連続圧力到達時間は、95〜103秒区間で1.16→7.98秒、
116〜142秒区間で0.96→25.98秒へ変わる。
これは保存された圧力列の判定結果であり、実機での前進を保証しない。
独立ROSの人工センサ試験では準備時の周期的な4 kPa偏差、30 msピーク中の
指令保持とその後の継続、持続過圧停止、センサ途絶停止を確認した。
