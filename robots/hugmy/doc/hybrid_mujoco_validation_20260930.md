# C/D実MuJoCo検証記録 — 2026-09-30

## 結論

自動目標到達・停止後の前進維持・姿勢安定を同時に満たす成功は未確認。
単発動作で停止後にも前進が残る試験はあるが、連続動作の成功とは区別する。
制御の単体テスト合格と、実際に進むことを分離する。
実機での再試行を勧める段階ではない。

**以下の旧探索の記録・起動例は履歴。現行の単発識別経路については末尾の
「単発識別＋連続牽引」を参照。底面の終端条件も現行は30 kPa保持へ変更した。**

ユーザー指定の円筒直径は100 mm。最初の切り分けではモデルの質量・摩擦・接触剛性は変更していない。
本検証では一時コピーしたMJCFの本体初期zを0.165 mとした。プラグインが
本体と円筒へ共通に加える0.1 mのオフセットは維持。アーム初期圧30 kPa、
底面初期圧0 kPa。元MJCFは変更していない。

## 実機bag cd_4の停止

対象：`walk_inchworm_cd_4_2026-09-30-01-14-17.bag`。
時刻はbag開始からの秒。計算時間予算により全候補を検査しない周期もある。

| 時刻 | 探索目標/rotor | 主な予測棄却 | 実測roll |
|---:|---:|---|---:|
| 6.38 s | 1.5 N | 角度/角速度2候補、左右差25候補 | −2.9° |
| 23.16 s | 1.5 N | 角度/角速度46候補 | −2.9° |
| 42.52 s | 2.5 N | 角度/角速度30、左右差4、roll2候補 | −3.0° |
| 113.56 s | 3.0 N | 角度/角速度6、左右差40候補 | −3.0° |

探索目標は増えている。一方、42.52秒の停止直前の実出力指令は約0.66/1.15 N。
6 N上限へ達したのではなく、予測不成立による減速・再把持で出力が途切れている。
62.51秒付近では安定平均位置が取得できず再把持待機がタイムアウトした。

角加速度の局所補正を`bias*t`で角速度へ加えると、ノイズによる±0.5 rad/s²の
補正が2秒先では±1 rad/sになる。bag診断の近似リプレイでは補正値の飽和・
符号反転が見られた。診断は出力更新後の値なので、完全な計算再現ではない。
今回、過渡応答`bias*tau*(1-exp(-t/tau))`へ修正した。tau=0.12秒では
同じ補正の角速度寄与は±0.06 rad/s以内になる。角度・roll等の保護閾値は緩めていない。
この修正で実機の停止全てが解消したことまでは未検証。

1. MuJoCoのSpinalインターフェースが飛行前にIMUを静止値へ置換していた。
   PWM-testによるパーチング動作は飛行状態へ入らないため、実際に傾いても
   コントローラへ正しいgyroが届かなかった。Hugmyで
   `simulation/physical_imu_on_ground: true`を指定し、物理IMUを使うよう修正。
   他ロボットの既定値は従来どおりfalse。実機ファームウェアは変更していない。
2. 安定平均の判定に生データの最大−最小を使うと、既定のmocapノイズ1 mmだけで
   2 mm幅を超え、準備が進まなかった。4小窓の平均の幅へ変更した。
   速度、鮮度、欠落、最新値の急変チェックは維持する。
3. 初期アーム圧と初期底面圧を別々に指定できるようにした。
   `initial_bottom_pressure`省略時は従来の`initial_pressure`を継承する。
   本検証以外の初期圧の既定値は変更していない。

現設定では移動制御を外しても初期把持が維持されず、前進制御の物理比較の前提が
成立していない。円筒径だけでなく、初期接触配置・圧力による曲がり・接触摩擦の

補助的な仮想把持力の接線方向成分は速度比例で、静止接線ばねはない。
ただしMuJoCo本来の接触摩擦もあるため、それだけが転落原因だとは断定しない。
摩擦値を都合よく大きくしたり、本体を固定したりして成功扱いにはしていない。

移動中の連続推力・底面応答 → 再把持後の安定平均による目標到達。

## 続報：静止把持モデルの修正

ユーザーの了承後、仮想把持の接線力へ弾性せん断を追加した。

```
接線変位 += 接線速度 * dt
試行接線力 = -kt * 接線変位 - ct * 接線速度
接線力の大きさ <= mu * 法線把持力
```

接触面法線が変わると変位を接線面へ射影する。滑り時は力を摩擦限界へ戻し、
変位も補正して蓄積過大を防ぐ。減圧・範囲外・法線力消失・エピソードリセットで
変位をリセットする。本体位置を固定する拘束ではない。

`grip_tangential_stiffness: 180.0` N/mは暫定値。摩擦係数1.2、把持力係数
0.08 N/kPa、法線剛性180 N/mは維持した。`grip_tangential_stiffness: 0`
で従来の速度比例だけの接線力へ戻せる。MuJoCoの通常接触は維持している。
この追加力は従来からの簡略なインフレータブル把持表現の修正であり、
皮膚・接触面積・実機の摩擦係数を同定したものではない。

また、アーム端へ力を加える際の速度を、リンク重心速度ではなく作用点速度
`v_origin = v_com + omega cross (x_origin-x_com)`へ修正した。

実機bridgeを起動せず、自動で停止・後片付けする。**下記は開発用再現試験であり、

```bash
  --output /tmp/hugmy_cd_physics_check --seconds 80 --distance .01 \
  --bottom 20 --mix .75 --contact-z=-.12 --rear-pressure 5 \
  --pressure-limit 50 --retain-grasp
```

3本以上の把持・最終roll±8°・roll変化15°未満・横変位/高さ変化20 mm未満・

## 高摩擦シミュレーションの起動

通常の `bringup.launch` は摩擦・円筒径の既定値を維持する。専用fixtureは
`hybrid_high_friction_mujoco.launch`。実機のmasterと混ぜないこと。
起動だけでは移動指令は出さない。これは検証用fixtureであり、安定した連続前進の
完成設定ではない。

```bash
export ROS_MASTER_URI=http://localhost:11321
roslaunch hugmy hybrid_high_friction_mujoco.launch headless:=false
```

別端末でも同じ `ROS_MASTER_URI` とワークスペースを設定してから実行する。
加圧とセンサの初期化を待ち、サービスが成功したことを確認する。

```bash
export ROS_MASTER_URI=http://localhost:11321
rostopic pub -1 /quadrotor/attitude_pressure_controller/target_attitude \
  geometry_msgs/Vector3Stamped "{vector: {x: 0.0, y: 0.0, z: 0.0}}"
rosservice call /quadrotor/attitude_pressure_controller/enable "data: true"
rostopic pub -1 /quadrotor/attitude_pressure_controller/inchworm_command \
  geometry_msgs/Vector3Stamped "{vector: {x: 1.0, y: 0.0, z: 0.03}}"
```

`z: 0.03` は前進目標30 mm。止める場合は同じサービスへ `data: false` を送る。
円筒径は `cylinder_radius` の2倍。既定では直径150 mm、把持摩擦4.5、表面摩擦4.0、
接線剛性1200 N/m。底面30 kPa、各前方ロータ6 N上限を維持する。
`lift_pressure_gain` は伸展中だけの圧力FBゲインで、既定20 kPa/s/rad。
比較用に60も試すが、滑り段階の圧力波形や推力上限は変更しない。

自動検証は任意の未使用出力先を指定する。こちらは独立masterを自動で作成・終了する。

```bash
python3 robots/hugmy/test/validate_hybrid_mujoco.py \
  --output /tmp/hugmy_high_friction_check --seconds 130 --distance .03 \
  --cylinder-radius .075 --grip-friction 4.5 --surface-friction 4 \

```

前進目標、停止把持、姿勢、初回の移動量、反復数のいずれかが未達なら非ゼロ終了。

最短時間を延ばしても、接触・実測圧力の成立条件や即時安全保護を無効にはしない。
`--require-forward-cycles 3` を指定すると、各1 mm以上の保持前進が3回連続しない限り
検証を失敗にする。通常の `--require-cycles` は再把持計測回数なので、両者を区別する。
結果JSONの `cycle_retained_mm` と `consecutive_forward_cycles` に対応する。

途切れることを確認した。これらは物理的な前進成功を示すものではない。

## 2026-10-01 連続前進の合格結果

滑り未成立後に推力を0 Nへ戻し、前後を低圧にしてから前方0 kPaの伸展試験へ
入る順序へ修正した。減圧による受動変形と推力による伸展を別の基準から計測する。
初回伸展推力は次周期の高速接近に利用するが上限制限にはせず、接触が変われば
角度・角速度を見ながら最大6 Nまで再探索する。底面によるsoft pitch変化では
推力を減速し、期限内に戻れば再開する。roll悪化は共通姿勢復帰へ引き継ぐ。

オンライン軌道候補は基準軌道で3回の保持前進を確認するまで変更しない。
これにより、毎周期の探索変更が連続性を崩さないようにした。確認後だけ、初期m補正と
力倍率の有限候補を停止再把持後の実測結果で選ぶ。

合格した条件と結果は以下。出力は `/tmp/hugmy_cd_stable_final` に保存した。

- 円筒半径75 mm（直径150 mm）、把持摩擦4.5、表面摩擦4.0、接線剛性1200 N/m
- 底面30 kPa、前方・後方圧上限30 kPa、後方低圧5 kPa
- 各ロータ6 N上限、伸展探索1 N/s、牽引最短1.5秒
- 停止再把持後の周期前進量: 9.90、3.05、7.39 mm
- 停止後平均前進量20.75 mm、3周期連続前進、最終推力0 N、4アーム把持
- 最終roll −1.58度、試行中roll変化最大4.67度、停止後位置窓0.163 mm
- body z低下11.0 mm、横変位8.56 mm。検証の各20 mm上限内

初回滑り試験の一時変位は11.21 mmあったが、後方圧力1周期にわたる定常速度条件を
満たさなかったため滑り継続には入っていない。これは「全く滑らない」条件ではなく、
一時的な揺動を滑り成功として誤認しなかった高摩擦条件である。

再現コマンド:

```bash
python3 robots/hugmy/test/validate_hybrid_mujoco.py \
  --output /tmp/hugmy_cd_stable_final_recheck --seconds 180 --distance .02 \
  --cylinder-radius .075 --grip-friction 4.5 --surface-friction 4 \
  --grip-stiffness 1200 --pressure-limit 30 --rear-pressure 5 \
  --lift-seconds 10 --lift-rate 1 --pull-min-sec 1.5 --retain-grasp \
  --require-forward-cycles 3
```

make.852でビルドし、全25本の単体・ソース検査に合格した。実機での接触応答と
圧力遅れは未検証なので、一般の実機既定値は変更せず、上記値はMuJoCo専用launchの
既定値にだけ反映した。

同じ制御を独立起動した `/tmp/hugmy_cd_stable_repeat2` でも、周期前進量は
9.90、6.38、8.77 mm、停止後合計25.12 mm、最終推力0 N、4アーム把持、
最終roll −4.59度だった。旧検証器は横移動21.72 mmを20 mm閾値で失敗にしていたが、
前進中の横移動は許容する要求に合わせ、通常移動の既定許容を30 mmへ変更した。
横移動量は結果に残し、転落検出・roll・高さ・把持・停止条件は緩和していない。
