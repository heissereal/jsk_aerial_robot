# Action Cの単発試験と連続牽引

## 実装の位置づけ

2026年9月30日の依頼に対応したAction Cの実行経路。滑りと荷重軽減を
各一度の連続入力で調べ、その応答から屈曲・牽引へつなぐ。
旧来の底面圧とmを繰り返し探索する処理は、アクチュエータ指令経路から外した。
識別結果は同じ移動指令の間だけ保持し、新しい指令でリセットする。
停止後にも残る変位と姿勢維持は、単体テストとは別にMuJoCoで検証する。
実機での性能・後転しないことを保証する実装ではない。

主な実装は `include/hugmy/control/hybrid_single_pass.h` と
`src/control/hybrid_locomotion.cpp`。Action A/B/Dの動作は変更しない。

## 動作の流れ

1. 全アームを把持圧にし、底面を30 kPaへ加圧する。膨張後の安定平均xを
   開始位置として目標を設定する。膨張だけの変位は移動へ加算しない。
2. 前方の角度をおおむね80〜100度に保ちながら、左右共通推力を0.25 N/sで
   連続増加する。どちらかの実測圧が直前の指令から2 kPa以上遅れている間は
   推力を減らさず、その場で増加だけを止める。許容伸展の最後2度では共通の
   増加率を連続的に0まで下げ、圧力による屈曲が追いつけば再開する。
   片側だけの通常減推力は行わず、目標を3度以上越えた場合だけ安全減推力する。
   後方は低圧と把持圧の指令を周期的に切り替える。最初の実測減圧を確認後、
   再把持期間中にも推力探索を継続する。前進速度1.5 mm/s以上の証拠が
   漏れ積算で0.3秒あり、同時に正味xが2 mm以上進んだ場合だけ滑り成立とする。
3. 滑りが不十分なら推力を0 Nへ戻し、後方の再把持を確認する。その後、
   **後方は30 kPaのまま**、前方だけ0 kPaを指令し、前方の実測圧が5 kPa以下になるまで待つ。
   減圧による受動伸展と推力による伸展を分け、ここから角度の基準と探索時計を設定する。
   前方0 kPaのまま推力を上げ、初回は各腕の3関節和が絶対45度付近へ向かう過程で
   伸展開始推力を同定する。相対8度は伸展開始の確認だけに用い、motion 2の完了条件には
   しない。絶対45度へ到達した腕だけを個別にラッチして推力を下げる。途中で角速度が
   小さくなっても接触限界や完了とは解釈せず、roll安全制限内で推力探索を続ける。
   角速度予測は目標前の推力ブレーキには使うが、未計測の到達判定には使わない。
   成立時の左右別の絶対bend角を保存し、次回以降は開始角が変わっても同じロータ姿勢を
   各腕独立に目標とする。
   初回だけ0.7 N/s以下で探索し、各アームが伸展し始めた推力・実測圧・開始角を記録する。
   絶対角FBが負荷に対して定常偏差を残し、45度手前で伸展が止まった場合も、同じ
   0.7 N/sで推力探索を再開する。PD出力だけで未達を成功扱いしない。
   2回目以降は8 N/sで立ち上げるが、下記の角速度・roll・推力上限を常に優先する。
   実測角速度が伸展を示したら速い増加をやめ、角速度に応じて増加を抑える。
4. 伸展角速度と残り角度から目標到達までの時間を予測する。後方の実測圧を0 kPaへ
   初回は、排気する所要時間（圧力遅れ＋圧力/排気速度＋0.1秒余裕）に入り、かつ**両前方が
   目標まで5度以内**になった時だけ、後方を先行して0 kPaへ排気する。瞬間的な高速
   伸展だけで早期排気しない。2回目以降の8 N/s動作は排気応答より短いため、motion 2
   開始と同時に後方0 kPaを指令する。実測後方圧は30 kPaから連続的に下がるので、
   前半のアンカーを残しつつmotion 3へ同期させる。2回目以降は各前方アームについて
   個別に目標到達をラッチする。実測伸展開始後は空気圧遅れを加えた予測角に応じて
   0〜10 kPaの終端ブレーキ圧を連続的に増やす。
   到達後はそのアームの推力を伸展開始推力より小さくして、最大10 kPaの圧力と
   実測角度・角速度FBで保持する。未達側だけが探索を続け、両方が保持帯に入ったら、
   後方の実測圧を待たずmotion 3の屈曲・牽引へ移り、後方0 kPa指令はそのまま継続する。
   これにより目標到達後も前方を0 kPa・伸展FBに置き続ける振動を避ける。
   時間切れや姿勢ブレーキを「荷重軽減の成功」に置き換えない。
5. 試験前の実測把持角へ屈曲させる。初期は上向き力を残しながら水平力を増やし、
   屈曲後半は上向き要求を減らす。実測の推力方向へ要求力を射影するため、
   水平付近でcos角の逆数を使って推力を発散させない。
6. 両前方が実測把持角の2度手前まで戻り、実測圧が把持圧−3 kPa以上、角速度0.2 rad/s未満が
   0.2秒続けば再把持として後方を加圧する。MuJoCoでは両前方の把持フラグも要求。
   実機では圧力と角度による代理判定であり、接触力の保証ではない。
7. 後方の実測圧が24〜28 kPaへ戻るのに合わせて前方推力を下げる。
   この受け渡し中もrollを悪化させる推力を減少側だけで補正する。
   底面は通常30 kPaのまま、停止後の平均x・pitchの安定を確認する。
   未達なら識別を繰り返さず、既に得た滑り条件または伸展量で次の動作へ進む。

圧力指令だけを根拠に屈曲済みとはしない。屈曲中は圧力の実測充填速度・遅れ・
予測誤差から到達時間を見積もり、最大0.5秒の角速度予測へ利用する。
初回同定が完了した後の不利なpitchでは、実測充填速度・遅れと伸展角速度から
0.6秒以内の到達を予測する。
ただし角速度予測が実測進捗より先行できる量は目標軌道の12%までに制限し、
breakaway直後の角速度スパイクで加圧が早まり、伸展そのものを止めないようにする。
予測伸展率55%から前方圧を単調に上げ、60%で最大3 kPaにする。これは伸展を
止めずに屈曲応答を開始するためのパイロット圧であり、本加圧はmotion 3で行う。両前方の伸展を
同時に確認し、かつ実測圧が2 kPaへ到達してからmotion 3へ渡すので、指令だけで
屈曲開始とはみなさない。両腕が最低50%まで前送りされ、実測圧2 kPa以上で実際に
屈曲方向へ反転した場合は、各腕の最大伸展を保持して60%の同時到達を待たずに渡す。
初回は平坦・傾斜によらず各腕の実測絶対bend角が45度へ到達してから屈曲へ渡す。
傾斜重なりはこの同定完了後の通常strideだけで有効にする。次回以降は初回に実測した
左右別の絶対bend角と、そこへ到達するまでに必要だった最大推力を
基準軌道として再現し、一律8度や固定0.85倍にはしない。初回の識別動作は通常strideの
モデルから除外する。以後の同一候補で、再把持・底面減圧後の前進量が近い値として
2回以上得られた場合だけ、安定strideとして利用する。

残距離は安定strideと10 mmの基準から分割する。例えば50 mmに対して10 mmが安定なら
10 mmを5回、20 mmに対して8 mmが安定なら10 mmを2回とする。最後に4 mmだけ残す
ような分割は避け、その残差を前の動作へ配分する。逆に残差がほぼ1strideなら、全動作を
不必要に強めず、弱めた1回を追加する。必要前進量と実測strideの比をそのまま使い、固定
1.5倍にはしない。1.5は1回の変更上限にすぎない。伸展量と屈曲時推力には比の平方根を
それぞれ掛け、片方だけを急変させない。短縮・強化した試行も倍率付きで保存し、倍率で
正規化して次の予測へ戻す。独立した通常動作の20度伸展保護、6 N推力上限、roll保護は
常に優先する。
短い予測は角速度から作るが、
実測屈曲からの先行量を制限し、推力増加の許容量も実測屈曲量で制限する。
準備・再把持境界の圧力判定は、目標±2 kPaで取得した後に±5 kPaを保持帯として使い、
±8 kPaまでの短時間外れだけを許容する。同じ境界で厳密な±2 kPa判定を重ねて
安定時間をリセットしない。生圧の異常・継続的な逸脱は別のハード保護で停止する。
力配分 `m = Fx+ / (Fx+ + Fup+)` はその結果の時系列であり、固定mの試行を
繰り返す方式ではない。推力ゼロ時の診断m=1は便宜上の値であり評価対象ではない。

## 伸展開始の学習と推力増加

伸展開始は、開始角から1度以上の伸展と、伸展方向の角速度0.02 rad/s以上が
0.10秒継続し、確認中にも実際の角度が伸展方向へ進んだ場合に記録する。
伸展は滑り試験中に始まる場合もあるため、滑り段階から観測する。
滑り試験で学習する場合は後方の実測減圧済みを要求する。motion 2では後方把持を
維持するため、この条件を要求せず、当該推力0.3 N超、機体roll/pitch角速度が
0.1 rad/s未満、姿勢ブレーキなしという条件も要求する。
1回の動作で各アーム1観測までとし、次回以降の観測は係数0.25の指数移動平均で更新する。
ただし観測圧の差が8 kPaを超えると記録を置き換え、把持圧での滑り試験と
0 kPaでの伸展試験の開始推力を平均して混ぜない。
3ラウンドのような更新回数上限はない。ただし、同一移動指令内の局所的な記録であり、
新しい指令ではリセットする。物体全般に通用する逆モデルではない。

速い接近を許すのは、実測圧が記録圧の−3〜+8 kPa、開始角差が10度未満で、
機体が大きく回転しておらず、アームもまだ伸展していないときだけ。
条件が合わなければ通常の探索速度へ戻る。角度と角速度が一致しない場合や
短時間の変化しか得られない場合は、開始推力を学習したとは扱わない。

初回motion 2だけは、45度以上の区間で伸展角速度を0.20 rad/sへ閉ループ制御する。
単発のNeuron IMUスパイクを0.25秒のフィルタで除き、目標へ近づくにつれて
推力増加率を0.7 N/sから連続的に下げる。目標±2 deg/sでは現在推力を保持し、
上限側を超えたらまず最大0.7 N/sで減力する。超過が0.15秒継続した場合だけ
最大3 N/sの滑らかな減力を許す。
角速度が再び不足すれば同じループで探索を再開する。45度未満は角速度FBを切り、
実測絶対bend角の到達判定を優先する。2回目以降はこの低速同定器を使わず、
初回に同定した推力へ高速接近する従来のmotion 2を維持する。
左右の角度を等しくするコスト・減力処理は使わない。両腕が異なる角度・推力でも許し、
roll FBと各腕の伸展量・角度・推力上限を維持する。固定の左右位相差は追加していない。

今回の変更は応答に合わせたランプと予測付き屈曲牽引であり、統一目的関数を解くMPCや
Gaussian processによるBayesian最適化ではない。既存の圧力応答推定を利用し、
そのモデルを最初から正しいと仮定して高速接近を許すこともしない。

## 次周期の軌道選択

通常strideから推力・左右別伸展量・力配分を記録する。次周期では開始角・roll・pitchが
近い過去の観測に限り、初期水平配分の補正（0、±0.05）と力倍率（0.95、1、1.05）の
7候補を試し、その後は平均評価と未確認度の小さなボーナスで選ぶ。強くする場合はまず
水平配分+0.05、次に力倍率1.05、最後に両者の組合せの順で原因を分離する。
基準候補で、停止後に1 mm以上残る前進が同じ接触文脈で2回再現し、正規化前進量の
ばらつきも許容内になるまでは候補を切り替えない。探索候補も1回だけで判断せず、
安全な正前進なら同条件をもう1回確認する。距離整形中は候補を同時に切り替えない。
これにより、識別直後の連続動作や距離調整を探索で崩さない。
候補集合による局所的なオンライン探索であり、大域最適性や安全探索の数学的保証はない。
候補は再把持後にだけ更新し、動作中のFBと同時に指令を取り合わない。

評価には停止再把持後の実測前進速度、推力二乗積分を前進量で割ったコスト、
記録された復帰時間を使う。1 mm未満の前進は追加で減点する。
未計測の終点・伸展未成立を成功候補にしない。なお、伸展成立前の異常停止や
未計測の復帰は現状この局所探索の記録対象外であり、復帰込みの最適化には限界がある。
力倍率を変更しても各ロータ6 Nなどの保護上限は変更しない。

## 初回伸展同定の不変条件

初回motion 2では前方圧力を0 kPa、後方圧力を把持圧に保ち、各前方アームを
実測絶対bend目標まで伸展させる。相対1度は伸展開始推力の検出、相対8度は
角速度追従への移行にだけ使い、完了条件には使わない。途中で角速度がゼロに
なった場合も接触限界とはみなさず、roll安全制限内で推力探索を続ける。
両腕が実測目標へ到達したときの最大推力を保存し、2回目以降はその手前まで
高速に接近してから角度・角速度FBへ接続する。初回同定ではbend 45度以上に限って
角速度スパイクを検出した制御周期は推力増加を停止する。0.25秒で平滑化した伸展速度を
0.20 rad/sへ追従させ、遅い間は最大0.7 N/sで探索、目標帯および高速伸展中は推力を保持する。
高速時に推力を減らして反動を作らず、独立したroll・絶対角・ハード角速度保護に安全停止を任せる。
45度未満では角速度を推力整形に使わず、
45度目標への実測到達だけを完了条件とする。

後方周期は滑り試験だけの指令周期で、0 kPaを2秒、30 kPaを1秒として繰り返す。
空気圧応答が遅ければ、その時間内に目標圧へ到達するとは限らない。motion 2では
周期切替を使わない。初回は30 kPaから開始して予測した終端付近だけ先行排気し、
2回目以降は短いmotion 2の開始時から先行排気する。motion 3では
前方の再把持確認まで後方を0 kPaに保つ。
時間切れ・センサ異常・安全停止は例外であり、低圧のまま待ち続けず全体を再把持する。

底面は動作中30 kPaを使い、姿勢復帰への引き継ぎ・手動停止・異常停止・安定終点計測では
0 kPaへ戻す。前進量は加圧前と動作後減圧後の安定平均を比較し、膨張だけの変位を除外する。

伸展中にrollと角速度から外向きの姿勢悪化を予測した場合は、移動推力を止めて
既存の共通roll復帰へ指令の所有権を渡す。目標位置と識別結果は保持し、復帰後に
自動再開する。pitchは底面膨張・伸展・圧力屈曲で意図的に変化させる軌道座標なので、
soft姿勢ブレーキには使わない。これにより屈曲中の短い荷重軽減区間で牽引推力が
消えることを防ぐ。pitchだけの異常・伸展未達タイムアウトなどはroll復帰で解決した
ことにしない。20度のハードpitch制限または伸展期限を越えた場合は異常停止する。
オペレータ停止、目標到達、センサ／圧力異常、90度rollは終了条件として維持する。
安全な未完了strokeは再把持・安定終点計測後に自動再試行する。

## 保護と観測

1基6 N以下、既存の上向き力上限、実測の伸展量・bend・roll・角速度・
pitch変化・後退・圧力・センサ鮮度・全体時間の制限を維持する。
初回の推力増加は0.7 N/s、2回目以降のmotion 2だけ8 N/sを許す。
実測伸展角速度による減速、roll FB、上向き力上限、1基6 N上限を先に適用する。
動作中と再把持中にrollモーメントの減少側補正を軌道の内側へ入れる。
予測姿勢が悪化すれば、力成分の要求に優先して推力を減らす。
これらは経験的な制限であり、モデル誤差に対する保証付きMPCではない。

MuJoCoのロータ部bendは関節角から得ているため、角速度も同じ角度座標の
差分を0.06秒時定数で平滑化する。以前の相対gyroとの符号不整合を避ける。
実機は既存のNeuron相対gyroを使い、このシミュレーション結果だけでは符号を変えない。

診断 `/quadrotor/attitude_pressure_controller/hybrid_locomotion` の先頭は版番号3。

## MuJoCoでの再現

リポジトリのルートから実行する。独立localhost masterを作り、実機bridgeは起動しない。
出力先は存在しないディレクトリを指定する。終了後に結果と全観測を残す。

```bash
source /home/miyamichi/ros/jsk_aerial_robot_ws/devel/setup.bash
python3 robots/hugmy/test/validate_hybrid_mujoco.py \
  --output /tmp/hugmy_single_pass_check --seconds 180 --distance .02 \
  --cylinder-radius .075 --grip-friction 4.5 --surface-friction 4 \
  --grip-stiffness 1200 --pressure-limit 30 --rear-pressure 0 \
  --lift-seconds 15 --lift-rate 1 --pull-min-sec 1.5 --retain-grasp \
  --require-forward-cycles 3
```

これは検証用コマンドであり、試験結果は `hybrid_mujoco_validation_20260930.md` を参照。
`--retain-grasp` は比較試験用に終端の前方屈曲圧を保持する指定であり、通常launchの
`hybrid_locomotion_retain_grasp_pressure` の既定値falseとは異なる。
この条件では2026年10月1日に、停止後1 mm以上が残る3周期連続の目標到達を確認した。
実機で同じ結果を保証するものではない。
`result.json` の `success` は到達ログだけでなく、停止後の平均変位・姿勢・把持・
推力ゼロ・底面目標への追従まで確認した結果。途中の前進量だけを成功とはしない。
